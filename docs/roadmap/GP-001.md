# GP-001 --- WLMOUSE Visual & UX Reference

## Status

COMPLETE

## Objective

Translate benchmark into non-infringing UX principles.

## Why

This GP is a roadmap gate that reduces ambiguity for dependent work and
protects the canonical architecture.

## Dependencies

GP-000

## Context

Read `AGENTS.md`, the Master Spec, Roadmap, relevant
specs/design/architecture docs, accepted ADRs and prerequisite closure
reports. Later GPs are context only.

## Scope

Validate ADOPT/ADAPT/REJECT across all major surfaces.

## Out of Scope

Final branding or UI code.

## Requirements

-   Follow canonical specs and accepted ADRs.
-   Do not silently expand scope or anticipate later features.
-   Document necessary deviations before implementation.
-   Preserve multi-brand architecture, Peru-first commerce, Admin
    operability and EC OS independence where relevant.
-   Produce validation evidence, not completion claims alone.

## Acceptance Criteria

-   Multi-brand, SEO, performance, mobile and accessibility adaptations
    explicit.
-   No unresolved critical contradiction with prerequisites.
-   Relevant automated/manual validation is recorded.
-   Repository state is clean or intentionally documented.

## Testing / Validation

Execute the smallest sufficient automated and manual validation set.
Include negative/edge cases for stateful, privileged or financial
behavior.

## Functional DoD

All scoped behavior/decision deliverables are complete and acceptance
criteria pass.

## Visual DoD

Required: high-quality visual and UX reference specification with precise pattern documentation, explicit ADOPT / ADAPT / REJECT decisions across all major surfaces, multi-brand and desktop/mobile adaptations, with no premature application UI or design-token implementation.

## Performance DoD

No unjustified performance regression.

## SEO DoD

Preserve the established SEO architecture.

## Security DoD

Follow established security architecture.

## Accessibility DoD

Preserve semantic and accessible interaction. User-facing interactive UI
must handle keyboard, focus, errors and reduced motion where relevant.

## Expected Deliverables

-   Scoped code and/or documentation.
-   Tests/evidence appropriate to the GP.
-   ADRs for significant architectural decisions.
-   `GP-001-CLOSURE.md` using the Closure Report template.

## Closure Requirements

Record base/closure checkpoint, files changed, decisions, validation,
acceptance criteria, deviations, risks/follow-ups, repository status and
PASS / PASS WITH NOTES / FAIL.
