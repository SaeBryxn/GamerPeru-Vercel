# GP-026A --- Storefront Visual Convergence

## Status

GP-026A CHK0 CONTRACT CANDIDATE / PENDING EXTERNAL APPROVAL / READY FOR EXTERNAL VERIFICATION

## Objective

Rebuild/refactor the customer-facing Gamer Perú storefront to achieve high-fidelity visual and interaction convergence with the current WLMOUSE storefront while preserving Gamer Perú's existing commerce/domain architecture, multi-brand model, Peru-first requirements, accessibility, SEO and security.

## Why

The owner has explicitly confirmed that the customer-facing storefront is not visually satisfactory and that the primary visual/UX benchmark is `wlmouse.com`. The objective is not a loose or generic "inspired by WLMOUSE" theme, but high-fidelity visual and interaction convergence:

- Equivalent component inventory where applicable.
- Equivalent information hierarchy.
- Equivalent composition and product-first visual dominance.
- Closely matched layout proportions.
- Closely matched spacing rhythm and fluid clamp curves.
- Closely matched typography hierarchy and font tracking/leading.
- Closely matched product-card anatomy (including horizontal spec highlight carousels and deterministic quick-add).
- Closely matched PDP commerce anatomy (adaptive gallery, sticky commerce panel, visual color swatches, option selectors, quantity controls, sticky buy bar).
- Closely matched desktop and mobile ergonomics.
- Closely matched long-form Product Story editorial presentation.

This exceptional gate is inserted between GP-025 and GP-026 to ensure the customer-facing presentation surfaces are fully established, validated, and visually frozen before the Admin Story Builder authors content for them.

## Scope

1. **Global Shell & Homepage Visual Foundation (CHK1)**:
   - Announcement bar with rotating messages (under strict Policy-Source Rule; unapproved SLAs/couriers omitted).
   - Minimalist header with centered/balanced navigation, search drawer trigger, mobile drawer trigger, cart drawer trigger, and 1.5px stroke iconography.
   - Multi-brand adapted desktop navigation and mobile navigation drawer.
   - Clean, restrained multi-brand site footer.
   - Homepage foundation: deterministic presentation configuration, campaign Hero, visual category doors, non-transactional editorial bands, comparison slider, BrandDiscovery, and visual slot-based TrustStrip rendering ONLY currently approved facts: PEN prices, manual Yape/Plin verification, and neutral multi-brand catalog identity. Unconfigured slots are absent from the DOM.
   - _Strict Exclusion_: CHK1 does NOT implement ProductCard V2, final product shelves, quick-add cards, or purchasable FeaturedProduct commerce logic.

2. **Product Card V2, Discovery Projections, Catalog Grids & Homepage Shelves (CHK2)**:
   - Additive public read projection (`ProductDiscoveryProjection`) delivering deterministic secondary media from `ProductMedia` joined to `MediaAsset` (`PUBLIC_MEDIA`, `IMAGE`, `variantId IS NULL`; when the primary ID is non-null, candidate `MediaAsset.id != products.primaryMediaId`; ordered by `ProductMedia.displayOrder ASC` then `ProductMedia.id ASC`; first key accepted by the public resolver), category-aware spec highlights, same-variant pricing tuple (`displayPrice`), and `quickAddVariantId`.
   - ProductCard V2 component with aspect-adapt image geometry, secondary hover flip, horizontal spec carousel, and deterministic action button ("Añadir al carrito" for proven single-variant items; "Ver opciones" linking to PDP for multi-variant or ambiguous items).
   - Category (`/categorias/[slug]`), Brand (`/marcas/[slug]`), and Search (`/buscar`) discovery grids.
   - Homepage product shelves (_Mouses_, _Teclados_, _Mousepads_) implemented canonically using ProductCard V2.

3. **Shared Product Commerce Convergence, PDP V2 & Homepage Featured Product (CHK3)**:
   - Converged shared commerce primitives: visual color swatches (`colorway`/`color`), dynamic option pills, inline quantity counter, Add to Cart actions, and Sold Out visual state.
   - PDP V2 commerce shell: adaptive gallery, sticky commerce panel (`lg:sticky`), sticky buy bar on scroll, conditional dimensions schematic only when exact Product/model data exists, and model-specific curated add-ons with sequential cart mutations.
   - Homepage FeaturedProduct commerce section implemented by reusing these exact shared commerce primitives (zero duplicated commerce logic).
   - Back-in-Stock notification subscription form deferred (non-functional data collection strictly prohibited).

4. **Public Product Story Renderer Convergence (CHK4)**:
   - Full redesign of public renderers for all 13 canonical Story block types (`hero_media`, `full_bleed_image`, `image_text`, `stat_highlight`, `spec_feature`, `video`, `gallery`, `comparison`, `dimensions`, `box_contents`, `technical_specs`, `faq`, `related_products`).
   - High-impact dark/light alternating editorial blocks, large typography, stat counters, and exploded mechanical schematics.

5. **Cart Drawer, Supporting Storefront Surfaces & Mobile Convergence (CHK5)**:
   - Slide-out Cart Drawer with compact item cards, quantity controls, and order summary.
   - Slide-out Search Drawer with instant predictive matching.
   - Mobile touch ergonomics (100vw gallery swipe, mobile touch targets >= 44x44px, sticky bottom purchase dock).

6. **Cross-Surface Visual Regression, Hardening & Closure (CHK6)**:
   - Side-by-side screenshot verification against live WLMOUSE captures across desktop and mobile.
   - Performance (LCP < 2.5s), WCAG 2.1 AA accessibility, and SEO verification.

- Database migrations during CHK0 or subsequent GP-026A checkpoints (zero runtime/schema delta).
- AI-generated product research or automated Story creation (handled in separate gates).
- Third-party payment gateways (Yape/Plin manual verification remains canonical for v1).

- Rendering unapproved customer-support/advisory promises or authorized-reseller/authorized-brand relationship claims.
- Duplicating commerce or card implementations across CHK1 and later gates.

## Operating Constraints & Invariants

- **Linear Gate Dependency**: CHK1 must not implement future-gate components. Product shelves belong to CHK2 with ProductCard V2. Homepage FeaturedProduct commerce belongs to CHK3 with shared commerce primitives.
- **Legal & Copyright Boundary**: Gamer Perú must use its own logo, red/white/dark brand identity, Peruvian copy, licensed/original photography, and domain structure. No WLMOUSE source code or proprietary assets may be copied.
- **Multi-Brand Retail Reality**: WLMOUSE is a single-brand manufacturer; Gamer Perú is a multi-brand retailer. Navigation, cards, and PDPs must display and filter brands cleanly without compromising visual restraint.
- **Policy-Source Rule**: Storefront commercial promises may render ONLY from an explicitly approved Gamer Perú business-policy source/configuration. If an approved value is absent, the UI MUST omit that promise rather than invent it. Courier brands, shipping guarantees, delivery SLAs/ETAs, warranty/returns terms, customer-support/advisory promises, WhatsApp, support hours/response SLAs, free-shipping thresholds, and authorized-reseller/authorized-brand status remain TBD and non-renderable until separately authorized or proven.
- **Read-Model Reality & Additive Projections**: Domain write semantics remain unchanged. Additive public read-model/projection extensions for `ProductDiscoveryItem` (deterministic secondary media, category-aware specification highlights, same-variant pricing tuple, `quickAddVariantId`) and PDP inventory availability are authorized under strict bounded, non-N+1 query constraints. `ProductVariant.status = 'ACTIVE'` does NOT equal "in stock". No `costCents` or internal data exposed.
- **Authoritative Quick-Add Contract**: Direct Quick Add is permitted ONLY when the read projection proves exactly ONE eligible public sellable `ACTIVE` variant exists (`quickAddVariantId: UUID`). Multi-variant products must render "Ver opciones" linking to PDP.
- **Same-Variant Pricing Rule**: Displayed starting/selling price and compare-at price must derive from the SAME deterministic eligible variant (`price ASC`, `displayOrder ASC`, `id ASC`).
- **Secondary Media Safety**: `ProductDiscoveryItem.primaryMedia` currently has presentation fields only and no `id`/`mediaAssetId`. The query must join `ProductMedia` to `MediaAsset`, require `MediaAsset.securityClass = 'PUBLIC_MEDIA'`, `MediaAsset.mediaType = 'IMAGE'`, and `ProductMedia.variantId IS NULL`; exclude the canonical primary with candidate `MediaAsset.id != products.primaryMediaId` when non-null; order by `ProductMedia.displayOrder ASC`, then `ProductMedia.id ASC`; and resolve the selected key through the safe public resolver. Never compare `ProductMedia.id` to `MediaAsset.id` or expose a browser-visible internal ID solely for this check. If no candidate qualifies, `secondaryMedia = null` and hover flip is omitted.
- **Safe Public Media Resolver**: Consumes already-authorized `PUBLIC_MEDIA` through the existing safe public resolver (object key validation, path traversal rejection, absolute URL injection rejection). Does NOT generate signed URLs.
- **Generic Variant & Spec Architecture**: Generic multidimensional variant resolution preserved (`color`/`colorway` aliases handled; generic attributes dynamically resolved; unknown dimensions fall back to variant title). Specifications extracted strictly from validated category schema + `specValues` without referencing fictional paths.
- **Conditional Product Data**: Exact dimensions are conditionally available only from validated `ProductSpecificationDetail.specValues` when the Product's category schema defines them, or from the canonical `dimensions` Story payload. Grip and hand-size guidance renders only when explicitly authored for the exact Product/model; missing data is omitted, never globally/category inferred, and creates no schema requirement.
- **Deterministic Merchandising**: Homepage featured product, shelves, and campaign media are driven by server-side static presentation configuration; no unapproved fallback or Admin toggle.

## Quality Gates

### Functional DoD

All scoped storefront surfaces render correctly across Desktop, Tablet, and Mobile with functional navigation, cart operations, variant selection, and catalog discovery.

### Visual DoD

Measured side-by-side high-fidelity convergence with `wlmouse.com` benchmark on typography, proportions, whitespace, product dominance, and component anatomy. Documented with comprehensive viewport screenshots.

### Performance DoD

SSR/Server Component architecture preserved. LCP < 2.5s on mobile/desktop, zero CLS regressions, optimized responsive images via Next.js `Image`, below-fold lazy loading.

### SEO DoD

Semantic HTML hierarchy, Server-rendered markup for crawlers, canonical URLs, BreadcrumbList, Product JSON-LD structured data, open graph tags.

### Security DoD

Server-side authorization and price/stock validation preserved. Zero client exposure of secrets or unescaped HTML. Safe Story validation intact.

### Accessibility DoD

WCAG 2.1 AA compliance: semantic landmarks, keyboard tab navigation, visible focus indicators, screen reader labels for icon-only buttons, live regions for cart updates, color not the sole state indicator.
