# GP-035 --- AI Customer Assistant

## Status

PLANNED

## Objective

Implement the public Gamer Perú AI chatbot for grounded product
discovery, recommendations, store support and authorized customer-order
assistance.

## Why

This GP is a roadmap gate that reduces ambiguity for dependent work and
protects the canonical architecture.

## Dependencies

GP-003, GP-004, GP-012, GP-014, GP-015, GP-020, GP-024, GP-025, AI_PROVIDER_ARCHITECTURE.md, AI_CUSTOMER_ASSISTANT_SPEC.md

## Context

Read `AGENTS.md`, the Master Spec, Roadmap, relevant
specs/design/architecture docs, accepted ADRs and prerequisite closure
reports. Later GPs are context only.

## Scope

-   Customer chat UI.
-   Provider-agnostic AI profile.
-   Public knowledge retrieval.
-   Product search/recommendation tools.
-   Product comparison.
-   Structured product links/cards.
-   Public store-policy Q&A.
-   Authenticated customer-owned order-status tool.
-   Privacy boundaries.
-   Prompt injection defenses.
-   Rate limits.
-   Escalation path.
-   Conversation/session model.
-   Usage/support analytics.
-   Admin assistant settings.

## Out of Scope

-   Payment approval.
-   Refund execution.
-   Price modification.
-   Stock modification.
-   Product publication.
-   Arbitrary database queries.
-   Direct EC OS access.
-   Autonomous purchasing.

## Requirements

1.  Model only accesses information through approved retrieval/tools.
2.  Public and private data zones are enforced.
3.  Product recommendations reference canonical catalog entries.
4.  Price/stock/order state always comes from application truth.
5.  The assistant can return direct product links and structured cards.
6.  Authenticated customer queries are ownership-checked server-side.
7.  Prompt injection cannot grant access to internal data/tools.
8.  Provider/model is selected through AI profiles.
9.  Unsupported information produces uncertainty/escalation rather than
    invention.
10. Conversation retention is configurable.
11. Usage/cost and resolution analytics are recorded.
12. The assistant can be disabled globally by Admin.

## Acceptance Criteria

-   Product Q&A grounded in catalog.
-   Product recommendations produce valid links/cards.
-   Product comparison works.
-   Public policy questions are grounded.
-   Authenticated order tool exposes only owner's orders.
-   Internal margin/supplier/EC OS questions do not expose restricted
    data.
-   Prompt injection test suite passes.
-   Provider/model profile can be changed without rewriting chatbot.
-   Escalation works.
-   Customer-assistant analytics are recorded.
-   Responsive/accessibility checks pass.

## Testing / Validation

Execute the smallest sufficient automated and manual validation set.
Include negative/edge cases for stateful, privileged or financial
behavior.

## Functional DoD

All scoped behavior/decision deliverables are complete and acceptance
criteria pass.

## Visual DoD

Chat UI must feel native to the premium Gamer Perú storefront.

Required: - desktop/mobile responsive; - unobtrusive launcher; - premium
chat panel; - product cards inside conversation; - loading/typing
state; - actionable links; - clear AI identity; - accessible
keyboard/focus behavior.

Avoid generic third-party chatbot appearance.

## Performance DoD

-   Chat must not materially degrade storefront initial load.
-   Chat bundle may be lazy-loaded.
-   Streaming may be used if supported by selected architecture.
-   Product/search tools should meet agreed latency targets.

## SEO DoD

-   Conversation URLs/messages are not indexable.
-   Chatbot code must not obscure semantic page content.
-   Repeated unanswered queries may feed an Admin SEO/content
    opportunity report, but publication is manual.

## Security DoD

-   Internal business data excluded from assistant retrieval.
-   Ownership authorization tested.
-   Prompt-injection/adversarial tests documented.
-   AI tools are allowlisted and schema validated.
-   Secrets and privileged Admin data never enter model context.
-   Rate limiting and abuse controls implemented.

## Accessibility DoD

Preserve semantic and accessible interaction. User-facing interactive UI
must handle keyboard, focus, errors and reduced motion where relevant.
