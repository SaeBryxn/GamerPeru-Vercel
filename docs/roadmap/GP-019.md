# GP-019 --- Manual Yape/Plin Payments

## Status

PLANNED

## Objective

Implement manual payment submission.

## Why

This GP is a roadmap gate that reduces ambiguity for dependent work and
protects the canonical architecture.

## Dependencies

GP-018

## Context

Read `AGENTS.md`, the Master Spec, Roadmap, relevant
specs/design/architecture docs, accepted ADRs and prerequisite closure
reports. Later GPs are context only.

## Scope

GP-019 receives an existing Order and an existing Payment record (status = 'UNPAID') created by GP-018 without recreating the payment shell (preserving Payment.order_id uniqueness). GP-019 owns: customer payment instruction presentation, interactive QR rendering, operation-code capture (PaymentSubmission.operation_code), optional voucher proof upload to private Cloudflare R2 storage, submission and resubmission UX, and transition into SUBMITTED / VERIFYING state (ADR-009).

## Out of Scope

Initial Order and UNPAID Payment creation (owned by GP-018); Privileged Admin payment verification workbench, verification notes, and approval/rejection decisions (owned by GP-028); Gateway automation.
