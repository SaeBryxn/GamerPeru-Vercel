# GP-053 --- Administrable Homepage

## Status

AUTHORIZED --- CHK0, CHK1 and CHK2 CLOSED ([CHK0](./GP-053-CHK0-CLOSURE.md),
[CHK1](./GP-053-CHK1-CLOSURE.md), [CHK2](./GP-053-CHK2-CLOSURE.md)); CHK3 (verification on the deployed

CHK4 require separate approval after each checkpoint closes. No migration may be applied to the
production database without explicit owner authorization.

## Objective

Let the operator manage the storefront home from Admin: reorder, show or hide sections, and
edit their text, images and videos, without code changes or deploys. Unify direct-to-R2 media
upload so no upload body is processed inside the Worker.

## Why

The home is hardcoded: two fixed YouTube embeds, literal copy, and seven images under
`public/images/home/` that do not exist and return 400. Every change needs a deploy, and the
most visited page depends on third-party embeds. Admin is a first-class product surface, and the
menu, products and Product Stories are already operator-managed; the home is the remaining gap.

## Scope

Delivered in checkpoints, each closed and approved before the next:

- **CHK0 --- Schema and read path.** Migration with `home_section_type`, `home_sections`,
  `home_section_media` and the seed of today's nine sections. Zod payload schemas per type. A
  cached section reader (`storefront-home` tag) with fail-soft defaults and fixture mode. The
  storefront home renders from the reader with zero visual change.
- **CHK1 --- Shared direct upload.** Extract `direct-media-upload` (request / browser `PUT` /
  `HEAD` confirm) with purpose policies. Product Story images move to it with no behavior
  change.
- **CHK2 --- Admin `/admin/home`.** Section list with wireframe thumbnails, drag and keyboard
  reorder, visibility toggle, per-type forms, image upload, section preview, confirmation dialog
  with outline preview for hide/delete, optimistic concurrency and audit.
- **CHK3 --- Video.** MP4/WebM and poster upload (`home_video`, `home_video_poster`), self-hosted
  video rendering in `VideoHero` and `FeatureVideo` with poster-first, reduced-motion and
  Save-Data behavior; YouTube kept as an optional source.
- **CHK4 --- Gallery migration.** Product gallery photos move to `direct-media-upload`
  (`gallery_image`) with mandatory client re-encode; the staging pipeline is removed once no
  caller remains.

## Out of Scope

- New section types or a home redesign (the nine existing sections only).
- Draft/publish revisions for the home (ADR-012 leaves room to add them later).
- Server-side video transcoding, adaptive streaming or captions authoring.
- Automatic deletion of orphaned media (explicit operator-confirmed cleanup is a follow-up).
- A new RBAC permission (`catalog:manage` is reused).
- Fixing the 404 menu links (`/guia-de-compra/*`, `/software/*`, `/soporte/*`), tracked
  separately.

## Requirements

- Follow ADR-012 exactly; document any deviation before implementing it.
- All writes authorized (`catalog:manage`) and validated server-side; the client is never
  trusted for authorization, order, visibility or payload shape.
- Payloads reference media only by `media_asset_id`; `home_section_media` is kept in sync in the
  same transaction.
- Every mutation uses `expectedVersion`; conflicts are reported, never overwritten.
- Every mutation writes an audit event that includes the previous content.
- The storefront skips and logs an invalid section instead of failing the page.
- Catalog-driven sections store only a source; prices and stock always come from the catalog.
- No upload body is read, hashed or transformed inside the Worker.
- The seed reproduces today's home exactly (order, copy, YouTube ids).

## Acceptance Criteria

- The operator reorders, hides, shows and edits every section and the change is visible on the
  storefront within one revalidation (immediately after the admin write's tag revalidation).
- Hiding or deleting a section requires confirmation with a preview of the resulting outline.
- Uploading a 25 MB MP4 and its poster completes without any `Error 1102` in Workers Logs and
  plays muted inline on desktop and mobile; under reduced motion only the poster is shown.
- An upload whose object differs from the signed type or exceeds the policy size is rejected
  and the object deleted.
- Two sessions editing the same section: the second save gets a conflict, not a silent
  overwrite.
- With the table empty or the database unreachable, the home renders the default sections.
- No 400 responses for home images; empty image slots render the existing empty background.
- After CHK4, gallery uploads no longer read bytes in the Worker and uploaded photos carry no
  EXIF/GPS metadata.

## Testing / Validation

- Unit: Zod schemas per type (valid, boundary, HTML injection, unknown fields, wrong media
  type); reorder density; version conflicts; media sync; upload token tamper/expiry/actor
  mismatch; `HEAD` mismatch deletion; reader fail-soft and skip-invalid behavior.
- E2E (fixture mode, never production): home renders from defaults with zero visual change;
  existing homepage, navigation and design-system specs stay green.
- Admin E2E against a local or branch database: reorder, hide with confirmation, edit text,
  image upload, conflict handling.
- Manual on the deployed Worker (owner-authorized): video upload and playback, Workers Logs CPU
  check, gallery upload after CHK4.

## Visual DoD

The storefront home is pixel-equivalent to today after CHK0. The admin editor follows the Admin

## Performance DoD

One cached read per revalidation window for the home. Video is poster-first with
`preload="metadata"`; LCP does not regress against the current YouTube-based home. Image
transformation volume stays within the ADR-004 presets.

## SEO DoD

Exactly one H1, required and bounded; alt text required for every non-decorative image; no
third-party embed required to render the hero; metadata unchanged.

## Security DoD

Server-side RBAC on every action; HMAC-signed, actor-bound, expiring upload tokens; `HEAD`
verification; HTML-free text; allowlisted external links; no secrets in the browser; audit
events for every write.

## Accessibility DoD

Keyboard reorder with live announcements; focus management in dialogs; labelled form fields
with inline errors; required alt text; videos muted, without autoplay under reduced motion, with
a visible play/pause control; Axe clean on `/admin/home` and on the home.
