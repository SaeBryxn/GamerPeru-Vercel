## Objective

Implement the AI Product Assistant that converts product names/model
identifiers into structured, sourced, reviewable Gamer Perú product
drafts.

## Why

This GP is a roadmap gate that reduces ambiguity for dependent work and
protects the canonical architecture.

## Dependencies

GP-003, GP-004, GP-022, GP-024, AI_PRODUCT_ASSISTANT_SPEC.md, AI_PROVIDER_ARCHITECTURE.md

## Context

Read `AGENTS.md`, the Master Spec, Roadmap, relevant
specs/design/architecture docs, accepted ADRs and prerequisite closure
reports. Later GPs are context only.

## Scope

- Single-product research.
- Batch product-name import.
- AI provider/profile selection.
- Product identity resolution.
- Structured specification extraction.
- Source/provenance storage.
- Confidence and conflict flags.
- Original product-copy generation.
- SEO draft generation.
- Media-candidate discovery/reference.
- Human review and approval workflow.
- Job status/progress.
- Provider/model audit metadata.
- Failure/retry handling.
- AI cost/usage telemetry foundation.

## Out of Scope

- Automatic publication without approval.
- Automatic pricing.
- Automatic stock updates.
- Automatic payment actions.
- Scraping/reusing copyrighted third-party media without
  authorization.
- Autonomous supplier purchasing.
- Unbounded web crawling.

## Requirements

1.  Admin can enter one product.
2.  Admin can paste a product list.
3.  System can classify or request review for ambiguous product
    identity.
4.  Research maps results into the canonical category-specific product
    schema.
5.  Research records sources.
6.  Conflicts remain visible.
7.  AI generates original Gamer Perú copy from verified facts.
8.  Product is created/updated as DRAFT by default.
9.  Admin can approve/reject proposed fields before publication.
10. Provider/model/profile used is recorded.
11. Individual batch failures do not fail entire batch.
12. Credentials remain server-side.
13. AI output is schema validated before persistence.
14. Usage/cost data is captured when available.
15. Admin must be able to use configured AI profiles without hardcoded provider logic in Product Manager.

## Acceptance Criteria

- Single import works end-to-end.
- Batch import supports partial success.
- Structured result validation works.
- Source/conflict information is visible.
- Provider/model is selectable through allowed profiles.
- At least one configured provider can be tested through the
  abstraction.
- Product remains draft until explicit approval.
- Credential leakage tests pass.
- AI failure leaves canonical product state consistent.

## Testing / Validation

Execute the smallest sufficient automated and manual validation set.
Include negative/edge cases for stateful, privileged or financial
behavior.

## Functional DoD

All scoped behavior/decision deliverables are complete and acceptance
criteria pass.

## Visual DoD

Admin import/review UI clearly communicates: - progress; - verified vs
unverified fields; - conflicts; - sources; - AI-generated copy; -
model/profile used; - media licensing uncertainty; - approval state.

## Performance DoD

Batch jobs must run asynchronously through the architecture chosen in
GP-003 rather than holding a single HTTP request open for large imports.

## SEO DoD

Generated SEO content remains editable and draft-only until approved.
AI must not create large amounts of thin/duplicate content
automatically.

## Security DoD

- No provider secrets exposed client-side.
- Provider-management permissions enforced server-side.
- AI cannot perform privileged commerce state changes.
- Uploaded/downloaded media paths are validated.
- External content is treated as untrusted input.

## Accessibility DoD

Preserve semantic and accessible interaction. User-facing interactive UI
must handle keyboard, focus, errors and reduced motion where relevant.

- Product research jobs.
- Admin AI import/review UI.
- Tests.
- Documentation.
- `GP-025-CLOSURE.md`.
