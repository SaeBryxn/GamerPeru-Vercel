# GP-055 --- Product Gallery Direct Upload

## Status

AUTHORIZED --- IN PROGRESS. The owner approved [ADR-013](../decisions/ADR-013-gallery-direct-upload.md)
and this design on 2026-10-15.

## Objective

Move product gallery photo uploads to the shared direct-to-R2 upload, so no image byte passes
through the Worker, while keeping every gallery behavior the operator relies on.

## Why

`finalizeCatalogMediaUpload` reads, re-encodes, hashes and writes each photo inside the Worker,
the path that exceeded the Workers Free CPU limit (`Error 1102`). Stories and home media already
use direct upload.

## Dependencies

GP-024 (Admin Product Manager), GP-053 (shared direct upload, closed). ADR-004, ADR-011, ADR-012,
ADR-013.

## Scope

1. `gallery_image` policy; always-re-encode option in `compressImageForUpload` (white background
   for the JPEG fallback); optional `variantId` in the direct-upload token.
2. `requestGalleryImageUpload` / `confirmGalleryImageUpload` services and actions (product and
   variant ownership, product advisory lock, `GALLERY` attach, audit, storefront revalidation,
   idempotent confirm).
3. Product editor switched to `uploadDirect`; finalize/retry state removed from the editor.
4. Production verification (owner session): upload a photo, confirm no `Error 1102`, check the
   stored object has no EXIF and the photo is upright, assign it to a variant, set primary,
   detach it.
5. Removal of the staging pipeline (`requestCatalogMediaUploadIntent`,
   `finalizeCatalogMediaUpload`, `image-normalizer.ts`, catalog `IMAGES` use) and its tests,
   replaced by tests of the new flow; `CLOUDFLARE_R2_PRODUCTION_SETUP.md` updated.

## Out of Scope

- Re-processing existing gallery photos.
- Deleting the staging bucket (owner task after removal).
- Changes to primary photo, variant assignment, ordering, alt text or detach behavior.

## Acceptance Criteria

- Uploading a 12 MP phone photo from the editor completes without any Worker read of the bytes
  and without `Error 1102`; the stored object is ≤ 4 MB, ≤ 2000 px, WebP (or JPEG fallback), with
  no EXIF and correct orientation.
- An object whose type or length differs from what was signed is rejected and deleted.
- A repeated confirm does not create a second attachment.
- All existing gallery operations keep working on photos uploaded either way.

## Testing / Validation

Unit tests for policy, re-encode option, token variant binding, confirm attach/idempotency/audit;
existing gallery operation tests kept green; `pnpm check`, `pnpm test:e2e`; production
verification as in scope item 4.

## Security DoD

Server-side `catalog:manage`; actor/purpose/variant-bound tokens; signed type and exact length;
`HEAD` verification; metadata stripped before upload.

## Accessibility DoD

Upload progress and errors announced as today in the editor.

Code, tests, updated R2 setup document, `GP-055-CLOSURE.md`.
